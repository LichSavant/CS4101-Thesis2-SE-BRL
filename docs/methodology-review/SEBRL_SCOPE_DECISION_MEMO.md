## Title and objectives

**Cover title, case-normalized from PDF page 1:**

> SE-BRL: A Modality-Aware Social Engineering Behavior Representation Architecture Using Machine Learning for Explainable Phishing Detection and Risk-Adaptive Defense

**Option A recommendation: retain this title.** “Using Machine Learning” remains
accurate because downstream phishing classification uses LR/linear SVM/RF/XGBoost.
It does not imply a learned behavioral-dimension model or transformer method.
Keep the approved artifact-level objectives (PDF pp. 22–23), clarify deterministic
states in methods, and describe the extension only as optional software/future
work. Do not add “semantic,” “neuro-symbolic,” “implicit intent recognition” or
“expert validated” as established thesis contributions without accepted changes.

**Option B title for adviser consideration only:**

> SE-BRL: A Modality-Aware Architecture for Deterministic Social-Engineering
> Evidence and Transformer-Assisted Review in Explainable Phishing Defense

This is not an approved replacement. It would require an explicit revised scope,

## Option A — smallest scientifically defensible continuation

Preserve the approved design. Freeze the operational twelve-rule/locator/
language/partial-availability specification; map it to the actual deterministic
instrument. Reconcile the eight support/availability values and matched E1/E2/E3
IDs/dictionaries, retaining separate U1 technical branches. Resolve ordinary
parser/interface failures and source custody, then obtain source-backed eligible
population/label/license/group/exposure facts. Freeze candidate search, paired
uncertainty, calibration/threshold/selection and efficiency settings. Under
separate exact authorization, verify data without fitting, then run the approved
controlled comparisons, selected-system freeze and valid final evaluation.

This option does **not** need expert annotators, behavioral-dimension training,
behavioral calibration or an NLI accuracy experiment. It still needs defensible
phishing-classification evidence and rule conformance. A model pipeline existing
or a software score of 95.45% is not that evidence. Null or negative E3–E1 results
must be reported honestly; no positive improvement is promised or manufactured.

## Option B — bounded semantic extension, not silently adopted

Retain the pinned optional NLI interface, hypotheses, constrained review controller,
strict original-span validation and R22 candidate-only boundaries. Keep deterministic
observations authoritative; semantic distributions request review and never fill
learned z slots, accepted behavioral labels or calibrated phishing probabilities.

Before a research claim, the adviser/researchers must decide the exact added
research question, the operational meaning of implicit/explicit/contextual
behaviors, evidence availability and identity audit requirements, appropriate
independent reference standard, corpus/consent/provenance/exposure policy,
reference construction/blinding/adjudication if applicable, sampling/uncertainty,
resource/model integrity, budgets and comparison design. Freeze all of that
before evaluation. Deterministic expected labels, synthetic humans, model outputs
or a second copy of the same rule cannot serve as independent semantic truth.

A review-only extension does not require training a behavioral classifier.
If human annotation is introduced, it is a change from the inspected approved
method, with explicit authorization and any applicable privacy/ethics review.
If accepted as Appendix-only engineering, do not present unvalidated semantic
benefits as main experimental results. No model inference or reference study is
authorized by this memo.

## Why clarification is needed now

The code contains several distinct instruments: legacy product keywords/point
risk; V13D observations/V13E preservation; V17/V20's two provisional decision
paths; canonical twelve-ID rules/typed trust ports; optional NLI candidates; and
an offline R22 wrapper. Shared names do not make their semantics identical.
Vera's reference-import/adjudication and learned-z placeholders are useful
preserved extension scaffolding, but the approved classifier inputs are
**deterministic support/availability**, not learned behavioral confidences.
The product demo's hardcoded strengths/weights are not the approved calibrated
classifier/precedence risk mechanism.
